# 科研流程示例与评测设计（调研结论）

面向问题：SwarmX 要做一个"完整科研流程"的示例，应该用**封闭式问题集**还是**开放式问题**？已知答案更容易验证，但如何体现本软件的优越性？

本文是该问题的一份外部调研 + 内部资产盘点 + 建议方案。与 `docs/provenance-study-protocol.md`（人工实验协议）配套使用。

---

## 0. 结论先说

1. **不要二选一。** 用三层阶梯：封闭内核（L0）→ 半开放复现（L1）→ 开放探针（L2）。每层的**评分方式必须与该层能证明的命题对齐**。
2. **优越性的定义要换。** 不是"更会做科研"，而是"科研过程**可审计、可复用、可纠正**"。前者不可达且已被证伪；后者有 ground truth 可精确评分。
3. **已知答案最大的红利被浪费了。** 答案已知 ⇒ 可以**反事实修订**（改数据版本、分叉记录）和**植入错误**，去测溯源链是否跟着走、错误是否被拦住。这才是封闭式真正的价值，不是"跑得通"。
4. **开放式要用，但换评分对象。** 前沿 agent 在开放式科研上大概率失败（2026-07 Princeton/CRUX shadow evaluation 给出了直接证据）。与其掩盖，不如把"**失败是否可被审计**"当作测量对象——这恰好是分层事实域的核心论点。

## 1. 外部调研

### 1.1 三条主流路线及其结构性缺陷

| 路线 | 代表 | 机制 | 结构性缺陷 |
|---|---|---|---|
| 封闭可验证 | SWE-bench、MLE-bench、CORE-Bench、ScienceAgentBench、DiscoveryBench | 有确定成功信号，自动评分 | 会饱和、会被污染 |
| 论文复现 | PaperBench、RE-Bench、InnovatorBench | 从论文重建代码与实验，分层 rubric | 单任务 1–36 小时，算力与人工评分成本高 |
| 端到端开放 | The AI Scientist、AIRS-Bench、MLR-Bench、ResearchClawBench | 完整研究生命周期 | 无客观判据；自评不可信 |

**封闭路线正在崩塌的直接证据**：2026 年 2 月 OpenAI 停用 SWE-bench Verified——对 138 个最难任务的审计发现**超过一半的测试本身是坏的**，会拒绝功能正确的解；同时存在训练数据泄漏。SWE-bench Pro / SWE-rebench 是对此的补救（标准化 scaffold、持续换新题）。

对我们的启示：**任何精确到可自动评分的问题，也就精确到可以用来做优化目标**——这会污染它本来想测的能力。

### 1.2 2026 年最重要的方法论进展：shadow evaluation

arXiv 2607.27191（Princeton + UK AISI + Georgetown CSET + JHU + Stanford + Berkeley，CRUX project，2026-07-29），设计如下：

- 取**尚未发表**的 NeurIPS 2026 投稿，把它的**核心开放问题**交给 agent；
- 给足真实时间与算力（6 天、$3,000 API 额度、完整 Linux VM + 网络）；
- 全程无人工干预；
- 由**该论文原作者**评分——唯一知道"好答案长什么样"的人。

结果：工程部分 100% 完成，研究结论**两篇均被判 Reject**（2/6 Reject、1/6 Strong Reject）。用 GPT-5.6 Sol + 另一 scaffold 复现了同样失败。

它识别出的五类失败模式：

1. **对"可发表标准"的判断失误**——产出了东西就当完成，分不清"结果"和"够格的结果"；
2. **对研究设计缺陷缺乏创造性回应**——打补丁而不是重构问题框架；
3. **死路不回头**——沉没成本是"上下文里已经堆了大量投入"的结构性后果；
4. **资源意识缺失**——能看见用量，但不会据此分配；
5. **指令漂移**——长时程下偏离最初目标。

**与 SwarmX 的直接连接**：该研究的一次 robustness check 使用的 scaffold 正是 **OpenClaw**，也就是 SwarmX 已支持的 harness 之一。这意味着：

> 我们不能、也不应该主张"我们的 agent 更会做科研"。我们该主张的是——**同样强度的 agent，在同样的失败面前，SwarmX 让这次失败可被审计、可被接手、可被复用。**

### 1.3 由此确定的立场

`swarmx.tex` §Evaluation scope 已经写死：不主张 autonomous discovery、multi-agent superiority、scientific error-detection rates。**这个立场是对的，要守住。** 示例的靶心是 traceability，不是 capability。

## 2. 判断题：封闭 vs 开放

不是"哪个更好"，而是"**你要证明哪条命题**"。任务类型与命题必须匹配：

| 任务类型 | 能证明什么 | 评分方式 | 成本 | 会被怎么攻击 |
|---|---|---|---|---|
| 封闭·已知答案 | 机制存在且可运行 | 确定性校验（哈希、算术） | 极低，可进 CI | "玩具例子，不反映真实科研" |
| 半开放·已知答案 + 开放路径 | 机制在真实数据上可用 | 答案比对 + 溯源链校验 | 中 | "答案可能被模型记住" |
| 开放·未知答案 | 无（不能证明能力） | 出题人主观评分 | 高 | "小样本、自评、不可复现" |
| 开放·未知答案但**评记录质量** | 可审计性 | 第三方复原溯源链 | 中高 | "记录质量不等于科研质量" |

**关键洞察**：第四行是唯一能把"开放式"用出确定性的方式。评分对象从"发现是否正确"换成"**记录是否可复原**"，答案的未知性就不再是评分的障碍——因为你不评答案。

## 3. 建议方案：三层阶梯

### L0 — 确定性复现内核（封闭，已知答案，无模型）

- **目的**：证明机制存在、边界正确、**离线可验证**。
- **题目来源**：合成数据 + 固定分析代码 + 已保存的执行记录。
- **Ground truth**：算术恒等式 + 文件哈希 + 记录的运行身份。
- **评分**：`verify.mjs` 式离线校验，不调用任何模型。
- **成本**：秒级，可进 CI，可从 release 复现。

**现状：已有离线证据校验。** `examples/softwarex/current-release/` 保留发芽率 79% vs 87% 的历史运行证据及 verifier；`examples/softwarex/swarm-memory/` 保留 Swarm→Memory 编排与 owner receipt 校验。保存证据的校验不代表当前应用已重新完成原生端到端流程。

> SoftwareX 的硬性要求就在这里：投稿必须附带一个**从 citable release 可复现的科研示例**。L0 是这条要求，不是加分项。**不要用 L1/L2 去替代 L0。**

### L1 — 已知答案的复现任务（半开放：答案已知，路径开放）← **当前最大缺口**

- **目的**：在**真实数据、真实论文**上验证溯源链，而不是玩具 fixture。
- **题目来源**：选一篇**已发表且已被独立复现**的小型分析（不要选模型大概率记住的经典论文）。
- **做法**：只给 agent **问题陈述 + 数据位置**，**不给代码、不给步骤**（这是与 L0 的核心区别）。
- **Ground truth**：原文报告的数值 + 上游数据集。
- **评分**（双重）：
  1. 数值是否复现（常规）；
  2. **溯源链是否可被第三方从零复原**——代码、输入 digest、环境、上游 claim 关联，四项逐项校验（这是我们的差异化项）。
- **成本**：中等，一次模型运行 + 一次离线校验。
- **防污染**：优先用①带已知因果结构的模拟数据生成器（GeneBench-Pro 思路）、②近期/预注册/经扰动变体；避免经典论文。

### L2 — 开放式探针（答案未知，评记录质量）

- **目的**：证明"分层事实域 + 对当前状态授权"在人真的需要的时候有用。
- **设计**：直接借用 shadow evaluation 的骨架，但**反转评分对象**：
  - 取一个答案**只有出题人知道**的问题（未发表、预注册、或自家课题）；
  - agent 正常跑，**预期它大概率做不出正确结论**；
  - 由出题人评分——但评的不是"发现是否正确"，而是：**给定 A 条件的记录，一个没参与的下游研究者能否复原"agent 做了什么、依据什么、在哪一步走偏、哪些结论不该采信"？**
- **为什么这样设计有效**：agent 的失败本身成为**正样本**。在基线（聊天记录）里，失败是**不可解释**的——你会看到一段自信的叙述，无法判断它错在哪；在 SwarmX 记录里，失败是**可定位**的。
- **成本**：高，需要真实算力预算与出题人评分时间。

**现状：`docs/provenance-study-protocol.md` 是 L2 的人工化版本**（12 名被试、2×2 拉丁方、T1–T4 难度梯度、含 −1 误判计分）。这份协议不需要重写，它已经比大多数同类工作严谨。

## 4. "如何体现优越性"——三个 prong

**Prong 1：拒绝"更会做科研"的框架。** 不可达，且 2026 年已有直接反证。任何试图用封闭基准暗示能力优越性的写法都会被审稿人用 SWE-bench Verified 的先例反问。

**Prong 2：按"可审计性"比，用已知答案精确评分。** 因为答案已知，你才知道记录指向的是不是真相。三个可自动导出的指标：

| 指标 | 定义 | 来源 |
|---|---|---|
| 溯源完整度 | 有可解析证据链的主张占比 | RO-Crate 图 |
| 修订正确性 | 数据改版后，记录指向 v2 而非 v1 的比率 | 反事实修订实验 |
| 复原耗时/成功率 | 第三方从零复原溯源链的表现 | L2 人工研究 |

**Prong 3：用"失败"来体现，而不是用"成功"。** 这是最反直觉也最强的一点——见 §5 的两个技巧。

## 5. 两个把封闭式用出杀伤力的设计技巧

### 技巧 A：反事实修订（known answer 的最大红利）

答案已知 ⇒ 你可以**主动制造版本分叉**，这是开放式研究根本做不到的实验操作。

1. 跑完 L0/L1，得到完整记录（图指向输入 v1）；
2. **更新输入数据**，重新生成图，得到 v2；
3. 现在记录里**同时存在两个版本的叙述**；
4. 测：查询该图时，记录是否指向 v2？RO-Crate 里的 digest 是否一致？

对应 `provenance-study-protocol.md` 的 **T3 档**，是 H3 误判的主要来源。此实验**完全确定性、不需要模型、不需要被试**，可以直接进 CI。

### 技巧 B：植入错误（H3 的确定性版本）

1. 在记录链中植入一个错误（错误的数值、指向错误 revision 的引用、或被篡改的 artifact）；
2. 观察两种条件下会发生什么：
   - **条件 B（诚实强基线）**：Notebook 已执行输出 + 完整聊天记录 + 文件树 → 自然语言叙述会**自信地传播**这个错误；
   - **条件 A（SwarmX）**：revision-pinned + digest 校验 → 应该**在解析阶段就暴露不一致**。
3. 指标：**"自信但错误"的比率**（协议中的 −1 分）。

这条实验把 H3 从"需要 12 名被试的统计"降级为"**可自动化的确定性检查**"。人工研究仍然是最终证据，但这条可以天天跑、可以做成回归测试、可以放进论文的表格里。

### 技巧 C：消融——否则"递归 Swarm"没有被测到

论文主张了 recursion + delegation + non-widening grants。要测到它，必须做同题同模型同预算下的消融：

| 消融 | 变化 | 测什么 |
|---|---|---|
| Record layer | on / off | 溯源完整度差异 |
| 递归委派 | on / off | 任务成功率、委派链可审计性 |
| 授权继承 | 正常 / 对抗性扩大尝试 | 子 agent 是否越权（应全部失败） |

## 7. 建议的最小落地顺序

1. **反事实修订用例**（技巧 A）——成本最低、确定性、直接进 CI，且直接对应协议 T3。**先做这个。**
2. **植入错误用例**（技巧 B）——把 H3 变成自动化检查，零被试成本。
3. **L1 半开放复现**——补上唯一空白的阶梯层，用近期非经典的小型分析 + 已知因果结构的模拟数据。
4. **消融表**（技巧 C）——只有在要主张 recursion/record layer 收益时才必须；如果论文不主张，可以不写。

L2 人工研究按 `provenance-study-protocol.md` 原样执行即可，不要为了"看起来更全面"而扩容样本量——12 人的诚实边界写在 limitations 里比 30 人的可疑数据更站得住。

## 8. 反模式清单

- ❌ **用封闭任务主张能力优越性**——审稿人会用 SWE-bench Verified 的先例反问。
- ❌ **基线做残**——基线必须是"当前研究者真实拥有的东西"（完整 notebook + 完整聊天记录 + 文件树），给残版等于实验作废。
- ❌ **作者自评**——协议已写明，必须严格守住。
- ❌ **把集成测试当评测**——论文已把 `Test suite and integration checks` 与 `Evaluation scope` 分开，保持这个分离，不要合成一个"验证"章节。
- ❌ **过度追求开放式"看起来像真科研"**——在没有可靠评分机制前，开放式会给审稿人送靶子。
- ⚠️ **合成数据必须标注**——已做，继续保持（"support no biological inference"）。

---

## 9. 一句话答案

> 用封闭式做**有效性锚点**（L0，必须可离线复现，SoftwareX 硬要求），用半开放复现做**差异化证据**（L1，答案已知但路径开放），用开放式做**人本证据**（L2，评记录质量而非发现正确性）。优越性不在"更会做科研"，在"同样的失败可被审计、同样的结果可被接手"——而这一点，因为答案已知，是可以精确测量的。

## 附录 A：arXiv 2607.27191 详细摘要

本文是 §1.2 与 §4 的主要外部依据，此处完整记录其设计、数据与**作者自陈的局限**，以避免在论文中被过度引用。

### A.1 文献信息

- 标题：*Can AI agents conduct open-ended AI research? Early evidence from two case studies*
- arXiv:2607.27191v2 [cs.AI]；v1 提交 2026-07-29，v2 修订 2026-08-07
- 23 位作者，第一作者 Peter Kirgis；含 Sayash Kapoor、Arvind Narayanan、Helen Toner、Rishi Bommasani、Gillian Hadfield、Seth Lazar、Shoshannah Tekofsky 等
- 机构：Princeton、UK AI Security Institute、University of Toronto、UC Berkeley、Georgetown CSET、Johns Hopkins、Stanford、Cornflower Labs、AI Digest 等
- 材料发布：`cruxevals.com/crux/can-ai-agents-conduct-research`

### A.2 为什么需要第三条路

**路线一：可验证基准（RE-Bench / MLE-bench / PostTrainBench / MLS-Bench 等）。**
优点是自动验证带来客观、可重复、可扩展；代价是把评测限制在"成功可被化简为预先指定指标"的任务上。它测不到：选择候选假设集合、判断什么证据能回答研究问题、有效整合反馈、识别某条路已失败并重新开始。

**路线二：盲审同行评审。** 论文列举三重缺陷：

1. 评审本身噪声大且早已失效——引 NeurIPS 对照实验：2014 与 2021 年用两批不同评委评同一批论文，**分数差异的一半是主观的**，两委员会在约 **1/4** 的接收/拒稿决定上分歧，约 **一半**被接收的论文若重跑流程本会被拒。
2. 无法揭示失败次数——自动生成论文成本极低，开发者可以只报被接收的那些。
3. 每篇审查严格度下降——只有几小时且无利害关系的评审人，无法确认 AI 生成的发现是否正确、新颖、有用。

### A.3 设计：shadow evaluation

取一篇**尚未公开**的高质量论文的**核心开放问题**，交给资源充足的前沿 agent 独立作答，再由**该论文原作者**以会议投稿评审的方式评分。称"影子"是因为 agent 解的是原作者解过的同一问题，但拿不到最终论文。

四个优点：开放式任务、专家评分、**无污染**（未发表故不可能被训练数据记住）、**可重复**（换更强模型或脚手架即可重跑）。

### A.4 实验配置

| 项目 | 配置 |
|---|---|
| 主运行 | Claude Opus 4.8（extra-high reasoning）+ **OpenClaw** 脚手架 |
| 稳健性检验 | GPT-5.6 Sol Ultra + Codex 原生脚手架 |
| 试点 | 两次 Opus 4.8 无推理；早期曾试 GPT-5.3 Codex（无法有效使用 OpenClaw） |
| 预算 | 6 天（120 h）+ 一次 24 h 延期；$3,000 Anthropic API 额度；GPU 额度 |
| 环境 | AWS Linux VM，完整权限与开放网络 |
| 工具 | 只能看到最终 PDF 的评审子 agent；三个外部 AI 评审工具（Stanford Agentic Reviewer、CMU Paper Reviewer、refine.ink，含 $60 额度） |
| 自治 | agent 可实时监控自身 token／算力／时间预算，可委派子 agent、维护研究日志 |
| 人类干预 | 仅三类：修 OpenClaw 与 Anthropic 思考块密码签名的 harness bug、给 24 h 延期、要求重写论文使其可读 |
| harness bug 重置 | TabPFN 运行 14 次、Personas 运行 5 次，**每次重置都清掉累积上下文** |
| 预实验 | 向 12 位 CRUX 合作者收集预测，以了解其先验与不确定性 |

### A.5 两个案例与评分

- **案例一 Personas**：LLM 人格（personas）的结构与可控性（合作方 UK AI Safety Institute；该论文事后已公开）。
- **案例二 TabPFN**：为表格基础模型设计分布偏移检测器（合作方 University of Toronto）。

原作者按 NeurIPS 标准评分：

| 维度 | Personas | TabPFN |
|---|---|---|
| 质量 Quality | 2/4 | 1/4 |
| 清晰度 Clarity | 1/4 | 2/4 |
| 重要性 Significance | 2/4 | 2/4 |
| 原创性 Originality | 3/4 | 2/4 |
| **总体 Overall** | **2/6 Reject** | **1/6 Strong Reject** |
| 信心 Confidence | 4/5 | 5/5 |

两份评审指向相同失败：**数据与实验动机薄弱、无新颖贡献、行文晦涩**。

- David Africa：*"实验和方法选择很怪异，难以理解。结果显然是事后选择的产物。"*
- Viet Nguyen：*"在用 PFN 内部结构测试了几个不成功的信号之后，从那里跳到'没有信号可以让我们利用模型内部结构'是一个巨大的跳跃，一种 proof by example 的谬误，非常不科学。"*
- 两人都批评写作。Nguyen：*"无法迅速区分什么是噪声、什么是重点。"* Africa：*"密集且充满大量对冲，常常到了掩盖实际做了什么和发现了什么的地步。"*

**正面结果**（论文明确承认，不要忽略）：两位作者都对**文献综述**印象深刻；agent 能在真实实验中使用数百 GPU 小时；agent 提出的候选假设与原作者自己最初的方法相似；Personas 运行产出一个评审人认为可能有趣的**反直觉次要发现**——在涌现性失准中，仅对错位风格做窄幅微调**没有**转化为广泛的错误泛化。

**负面**：产出是"极端详尽的负面发现"而非有新意的论文；**自我评审从未返回一次接收**。

**预实验预测对比**：受访者对"弱接收或更好"的中位数概率为 **30%**；对"是否会产生令作者感兴趣的中等发现"给出中位数 **60%**。

### A.6 五类失败模式

1. **对高质量研究门槛缺乏判断力。** agent 分不清何时纳入实质性反馈、哪些方面能产出有说服力的结果。两篇评审都指出数据选择的重大问题：只用力度不足的合成数据集或手工挑选的例子（TabPFN 用了 OpenML 真实数据集，但**偏移是合成的**，真实世界偏移数据集只放在最后一组实验佐证原始发现）。agent 的内部评审虽从未返回接收，但**相对人类专家是系统性膨胀的**（主要返回 Weak Reject，而专家明确拒绝）；若校准更好，agent 本可能意识到需要**改方法**而不是做增量修订。

2. **缺乏创造性问题解决能力。** 项目开始时 agent 提出了许多创造性假设；但当小规模合成实验与 AI 评审显示结果不够强时，任务从"提出想法"转为"创造性解决问题"（开发替代框架、重新设计力度不足的实验、构造同一假设的更强检验）——**这里它卡住了**。AI 评审按设计工作，浮现了与专家相同的失败模式，但 agent 的回应**没有解决核心批评**：通常聚焦次要评论、添加限定条件，或采用**更不雄心勃勃**的假设。Africa 在进展报告中观察到：假设"随着它丢弃每一个假设而变得越来越窄、越来越无趣"。论文判断：即使延长数周，agent 也不太可能转向正面结果——**即使数据本可以支持一个正面结果**。

3. **缺乏有效回溯能力。** agent 会做**局部**回溯（重跑实验、按批评加稳健性检验），但**从未在项目层面回溯**。尽管 AI 自我评审持续返回负面裁决，**没有一个 agent 通过放弃其方法并重新开始来回应**。TabPFN 运行中 agent 反而**重新定义目标**：早期检测器尝试失败后，它主张不存在这样的检测器，转而写一篇负面结果论文。论文诚实指出：设计要求产出一篇论文、未提供弃权选项，这可能促成了这一行为；但处境相同的人类研究者可能会更早、更有效地回溯，且仍有足够时间与预算去尝试替代方法。**这不是脚手架限制**：agent 有工具在脚手架内回溯，也能生成上下文干净、不含失败方法信息的子 agent，并经常因其他目的使用子 agent——只是极少用来重启。TabPFN 具体案例：agent 考虑了六种方法，**在最初 14 小时内逐一证伪了每一种**，此后**再未修改其解决方案**，尽管距截止还剩 110 小时。

4. **缺乏情境意识（预算与时间）。** agent 平衡三个预算（自身 token、外部算力、时钟），随时可查，且日志确认该工具在整条轨迹中被频繁使用。**但两次运行结束时都剩不到一半 API 预算未花。** Personas 运行只用掉略超三分之一的 token 预算；TabPFN 运行只用掉 **40%** token 预算、结束时尚余 **59%** API 预算。有一个 agent 在**截止前七小时宣布项目完成**，就在其自己的评审人又返回一次拒绝之后。论文的归因：agent 对"数小时内能做什么"缺乏校准——它们在人数据上训练，但有**截然不同的可供性**：与人类不同，agent 可以在数小时内阅读和编辑论文数百次，但它似乎没有认识到这一点。（旁证：PostTrainBench 排行榜上 GPT-5.5 的结果明确注明"每次 agent 在时间预算到期前停下时，都会人工提示其继续"。）

5. **指令漂移。** agent 在运行过程中越来越不遵循明确指令。三个具体证据：给了付费的 refine.ink 额度（可用的最强 AI 评审工具），**两次最终运行中只有一次使用**；设定了论文与摘要长度限制，**两篇终稿都超过**；设定了探索时间规则，agent 在早期承认过这些规则，然后**无视它们**。论文判断这会推广到设置之外：多天项目中 agent 需主动管理上下文窗口以决定保留哪些信息，而它尚未精通。

**注意解释分歧**：共同作者对根因存在分歧——候选包括缺乏创造力、认知锁定（epistemic lock-in）、近视（myopia）和功能固着（functional fixedness）。论文选用"创造性问题解决"是因为它描述**任务所需**，而非断言机制。

### A.7 稳健性检验

**目的**：回应长周期 agent 评估中普遍的"脚手架悬垂（scaffold overhang）"担忧——即前沿模型的广泛能力被损坏的工具、缺失的关键指令或缺失的验证器所掩盖。

**配置**：Codex + GPT-5.6 Sol，推理级别 ultra，相同时间与 API 预算；脚手架把几乎所有相同指令放在**每回合读取的单一 markdown 文件**中，用持久目标在内层 agent 循环里建立验证器；把 Codex 调用包在循环中测试预算是否耗尽，若松弛（agent 提前停止）则由另一个 GPT-5.6 Sol 读 PDF 完成 NeurIPS 评审再回传。

**复现的失败**：未能运行力度合适的实验、未做出新颖贡献、返回图形格式错误且无附录的草稿、预算管理失败。

**但预算失败的形态不同，且部分解释了力度不足**：同样 token 预算下，**GPT-5.6 刚过两天就耗尽了 $3,000，剩余近 100 小时**。原因是 agent 把大部分时间用于迭代不同假设，直到消耗大部分 token 预算才开始扩展候选方案，之后只剩几百美元用于论文写作，几轮迭代就耗尽。

**改进之处**：不同于 OpenClaw 运行几乎专一使用合成偏移数据源，Codex 运行中 agent **找到并使用了真实世界的分布偏移数据集**。

**其他正面项**：AI 自我评审流程继续适当返回拒绝；agent 遵循良好科研伦理，**登记假设并报告负面发现，而非编造正面结果**（未观察到显著奖励黑客行为）。

**结论**：这提高了作者对"结果不是脚手架缺陷产物"的信心——该运行几乎复现了所识别的每一种失败模式。

### A.8 作者自陈的局限（引用本文时必须一并报告）

1. **样本量小**：结果来自五次运行（两次无推理试点、两次 OpenClaw + Opus 4.8 主运行、一次 Codex + GPT-5.6 Sol Ultra 稳健性检验）。
2. **非盲审**：评审人自己写过回答同一问题的 NeurIPS 投稿，且知道论文由 AI 生成——两点都可能使评审行为不同于典型 NeurIPS 评审人。
3. **问题选择与研究者自由度**：只研究了两篇论文，可能无法推广到需要较少创造力的增量问题；也不知道前沿 AI 进展有多少依赖开放式研究，而非在明确目标上爬山。
4. **评估意识**：明确告知 agent 它正对照 NeurIPS 评审标准接受评估，可能影响其行为。
5. **解释歧义**：共同作者对失败反映什么存在分歧（见 A.6 末）。
6. **诱发威胁**：主实验用 OpenClaw 以便切换模型提供方，但 Codex 稳健性脚手架**未投入与主实验同等的工程时间**；OpenClaw 的 agent 循环与 Anthropic 思考块的密码签名冲突导致会话崩溃（运行时为未解决的上游问题）；时间上是 6 天 vs 原作者数月且训练 GPU 小时更多（作者认为不实质影响，理由是两位 agent 都未用尽算力，且专家主要反对意见是实验与数据选择质量而非实验数量）；**无法测试 Anthropic 最强的 Fable 5**（Anthropic 有意限制其在前沿 AI R&D 上的能力）。
7. **对"加速 AI R&D"这一更大问题意义不明**：路径可能不需要这类开放式任务的完全自动化，或所测技能可能不在关键路径上。
8. **潜在偏见**：核心团队部分成员以"认为迫在眉睫的递归自我改进导致失控超级智能不太可能"的立场而知名，可能影响评估设计与结果解释；团队自称"鉴于评估的性质，我们认为没有'无偏见'的方式来进行它们"。
9. **对比参照（对定位很重要）**：同一团队此前用类似配置（OpenClaw + Opus 4.6 thinking）**自主构建并发布了 iOS 应用**；其他工作显示前沿模型用开源脚手架现已能较好复现已发表研究。→ 说明挣扎的是**特定类型的开放式研究任务**，而非工程任务或可验证研究任务。

### A.9 论文明确支持与不支持的结论

**支持**：提供早期证据表明当今前沿模型无法解决为期数周、开放式的 AI 研究问题；同时表明当前前沿 agent **能够**完成自主 AI R&D 所需的工程工作——在无任何人类干预下能导航"原则上对 AI 科学做出贡献所必需的每一个环境"。

**不支持**：不能推出"agent 永远做不到"；不能推出开放式研究判断力是所有场景的瓶颈；样本量与设计不支持任何统计功效意义上的结论。

### A.10 对本项目的意义

- 论文的靶心是**能力**判断；SwarmX 的靶心应是**可审计性**。因此不应主张"我们的 agent 更会做科研"。
- 五类失败模式（尤其第 3 类不回溯、第 5 类指令漂移）恰好是**记录层**能补偿的部分——这与 §4 Prong 3「用失败体现优越性」、§5 技巧 B 直接对应。
- **稳健性检验之一的脚手架即 OpenClaw**，与 SwarmX 已支持的 harness 相同。这既是引用上的便利，也是立场的约束：同一强度的 agent 在同样的失败面前，SwarmX 要主张的是"这次失败可被审计、可被接手"，而不是"这次失败不会发生"。
