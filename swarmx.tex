\begin{abstract}
Agent-assisted research produces records across conversations, computations, files and later
knowledge use. SwarmX is open-source software that links these records while preserving native
agent sessions. It provides revisioned research records, content-addressed artifacts, recursive
delegation and source-linked memory with configurable write approval. A guided synthetic-data
example connects figure generation, recomputation in a separate session, a recorded claim,
approved memory and retrieval in a later session. Integration tests and artifact checks validate
the recorded workflow and persistence boundaries. SwarmX supports inspection and reuse of research
records across sessions; the example demonstrates software integration rather than scientific
discovery or comparative agent performance.
\end{abstract}

\section{Motivation and significance}
\label{sec:motivation}

LLM agents can search literature, run code, edit files, invoke instruments and services, delegate
work, and draft manuscripts. A single research result may consequently depend on a native
conversation history, several notebook or command executions, mutable workspace files, an
experiment record, review decisions, and knowledge carried into later sessions. These records have
different storage locations and lifecycles. A transcript records interaction but does not establish which
artifact version entered a claim; a file tree retains outputs but not the decision that admitted
them; and a workflow log does not by itself preserve the research question or later knowledge use.
The resulting fragmentation makes agent-assisted research difficult to inspect, resume, and
transfer.

These problems also occur with a single agent. Multi-agent execution is useful when a workflow
has separable research branches, needs distinct tool contexts, or assigns production and review
to different actors. Separate contexts let an analyst examine data while a reviewer inspects
original sources, and explicit delegation makes their responsibilities visible. Teams also add
communication and integration costs. SwarmX supports both arrangements through shared scientific
records and memory, with the number of agents chosen for the task.

The AI Scientist automates computational
machine-learning research from ideation through manuscript review; Co-Scientist uses an
asynchronous multi-agent process to generate and refine biomedical hypotheses; and the Virtual Lab
combines an AI principal investigator and specialist agents with human feedback and wet-laboratory
validation~\cite{lu2026,gottweis2026,swanson2025}. ScienceAgentBench instead
evaluates 102 executable tasks drawn from 44 peer-reviewed papers and shows that the evaluated agents
solve only a minority, even when expert knowledge is supplied~\cite{chen2025b}.
SwarmX provides infrastructure for such workflows by coordinating native agent runtimes and
linking the records produced by their scientific tools.

Computational-provenance systems supply essential parts of this infrastructure. Whole Tale captures
reproducible environments, AiiDA manages computational workflows, noWorkflow captures Python
execution, and ProvBook enriches notebooks~\cite{brinckman2019,pizzi2016,pimentel2017,samuel2018}.
Workflow Run RO-Crate packages workflow executions, and PROV-AGENT represents agent interactions
~\cite{leo2024,souza2025a}. The FAIR principles and RO-Crate provide the exchange layer for
discoverable, reusable research objects~\cite{wilkinson2016,soiland-reyes2022}. SwarmX applies
these ideas to connect records stored by native runtimes, scientific services and knowledge stores.

Contemporary agent systems increasingly represent claims and evidence explicitly. ResearchLoop
uses repository-backed task contracts and evidence gates to control claim admission; LEDGER
constructs audit graphs from observed agent sessions~\cite{xia2026,kim2026}. Artifact-centered
observability specifies claim-aware lineage, and PaperTrail presents claim-level provenance for
scholarly review~\cite{yin2026,martin-boyle2026}. SwarmX focuses on connecting the running workflow
to persistent research and knowledge records: native runtimes retain sessions, scientific services
store revisioned entities and artifacts, and curated memory carries sourced findings into later
sessions. Table~\ref{tab:related} summarizes these different emphases.

Retrieval-augmented generation (RAG) uses external knowledge to support generation
~\cite{lewis2020rag}, and Self-RAG combines retrieval with critique~\cite{asai2023selfrag}.
Experience reuse also has established precedents: Reflexion retains textual feedback, Voyager
accumulates executable skills, and Agent Workflow Memory extracts reusable procedures
~\cite{shinn2023reflexion,wang2023voyager,wang2024workflowmemory}. SwarmX integrates source-linked
scientific records with scoped, revision-controlled memory operations across native agents.
This store can supply curated knowledge to retrieval-augmented workflows.

Mokyr's useful-knowledge framework~\cite{mokyr2005} gives a broader rationale for joining
explanation and procedure. The framework distinguishes propositional knowledge about why a
technique works from prescriptive knowledge about how it is performed.
Applied to computational research, questions, hypotheses, claims, and evidence form the explanatory
record, while code, executions, configurations, workflows, and skills form the procedural record.
Their links allow a later researcher or agent to recover both the basis of a result and the process
that produced it.

We use this distinction and the FAIR principles as design guidance~\cite{mokyr2005,wilkinson2016}.
Figure~\ref{fig:architecture} groups the supporting functions into knowledge storage,
interoperability, quality control, and governance and incentives. This organization is our design
view; the implementation supplies local record management and workflow controls.

This article makes three contributions. First, it presents an architecture independent of a
particular client that connects native agent runtimes to append-only research records, content-addressed artifacts,
recursive delegation, sourced memory, and portable exports. Second, it implements source validation,
revision checks and configurable approval for knowledge creation, revision and deprecation.
Third, it provides executable artifact checks, current integration tests and a
recorded workflow linking native delegation, scientific artifacts and a subsequently retrieved finding.

\subsection{Software architecture}
\label{sec:architecture}

The system comprises a client, native conversation runtimes, SwarmX services, and user-controlled
resources with portable outputs (Figure~\ref{fig:architecture}b). The local Host
presents conversations and research objects to an Electron or browser client. It launches
unmodified upstream Codex ACP and Claude Agent ACP adapters, or the native Hermes and OpenClaw ACP
commands. Agent Client Protocol (ACP) connections carry session discovery, creation, reading, execution,
configuration and cancellation; recursive Swarms act as an ACP Agent upstream and ACP Client
downstream. Only the selected native integration loads. Native runtimes retain their histories,
agent loops, tools, authentication and permission semantics. The Host projects their reported
events into the client without taking ownership of native execution.

Each registered filesystem project has separate services, research records, an execution journal,
settings and workspace memory. Model Context Protocol (MCP) carries product-tool calls, and ACP
carries agent delegation. External ACP and Agent2Agent (A2A) entry points expose the same services;
the client receives Agent--User Interaction (AG-UI) events. Native runtimes and services retain
their records; the client displays transient projections. Figure~\ref{fig:architecture}a relates
these components to the design functions: persistent records, interoperability, review support
and workflow permissions. Resource allocation and institutional rewards remain external.

\subsection{Software functionalities}
\label{sec:coordination}

% 中文：解释记录与过程记录通过版本、摘要与证据关系连接。
SwarmX applies the useful-knowledge distinction by linking two families
of records. Questions, hypotheses, claims, and evidence form the explanatory chain; notebook cells,
experiment runs, artifact-generation records, code, and documented procedures form the procedural chain.
Revisioned locators, content digests, and explicit evidence relations connect the two across
services. This structure preserves both how a result was produced and why it entered the research
record.

% 中文：ScienceCore 为 Notebook、实验、图件、写作、科研记录、查询和导出提供紧凑工具接口，并可只读搜索本地 Zotero。只追加 SQLite Journal 记录科研实体及其关系，物化投影可由 Journal 确定性重建。工作区文件保持可变；文件注册为工件时经过类型核验、SHA-256 摘要和原子内容寻址发布。带 revision 的规范 sx 地址连接会话与这些对象，项目图可导出为 RO-Crate 1.3。图件还可以记录绘图代码摘要、脱敏运行环境和已核验输入来源。
ScienceCore provides a compact tool interface for notebooks, experiments, figures, writing,
research records, queries, and export, together with read-only search through the
\href{https://www.zotero.org/support/dev/web_api/v3/local_api}{Zotero local API}. An append-only
SQLite Journal records scientific entities and their relations, and materialized projections
rebuild deterministically from the Journal. Workspace files remain mutable; when a file is
registered as an artifact, it is type-checked, SHA-256-digested, and atomically published by
content address. Canonical, revisioned \texttt{sx:} addresses connect conversations to these
objects, and a project graph exports as RO-Crate 1.3. Figures can additionally record a
plotting-code digest, redacted execution environment, and verified input sources.

% 中文：Swarm 提供递归组合与显式委派；执行关系可供事后检查。
A Swarm exposes the same Agent interface as its lead, which may itself be another Swarm. The Host
provides explicit creation, status, session, message, and cancellation operations, with membership
held in memory. Delegation returns results while native agents retain their transcripts and
approval boundaries. Recorded parent--child execution links support inspection after a run;
in-memory membership does not provide automatic recovery of unfinished tasks.

\subsubsection{Knowledge curation and retrieval}
\label{sec:memory}

% 中文：Memory 通过显式整理积累知识；检索实现与知识治理相互独立。
SwarmX stores curated findings and procedures as readable Open Knowledge Format 0.2 Markdown
concepts in shared semantic memory. The store persists this knowledge across sessions and exposes
explicit search, read, create, update, deprecate, and lint operations through the Host's Memory
tool. Global and workspace scopes bound access; native agents retain ownership of conversation
histories and context management.

Memory records support source references, lifecycle metadata and SHA-256 revisions. Updates require
the previously read revision. The Host authorizes writes from a user-owned workspace setting;
per-write approval is optional and off by default. When enabled, writes become durable pending
proposals that only an authenticated browser action can approve or reject. A model-supplied
approval flag is rejected. Deterministic validation checks document structure, citations and
workspace-scoped Science references.

Knowledge accumulates through explicit authoring and optional background review. A user or agent
records an outcome and its sources; review can propose notes or concepts from bounded conversation
and tool-event snapshots. Automatic review is enabled by default, after ten successful prompts
or ten tool calls in one turn, and can be disabled per workspace. Review candidates pass the same
validation, revision and configured write-approval checks. Updates preserve previous bytes and
append to the change log.

Search ranks textual matches in titles, tags, descriptions and bodies; a subsequent read returns
the concept and revision. Bounded user/workspace notes and a vault navigation index are frozen
when a session is initialized. Existing sessions retain that snapshot across restart; new
sessions see updated notes and index entries. Full concepts are retrieved on demand. Explicit,
revision-pinned prerequisite edges reject cycles and support ordered loading. Upstream changes
mark dependent concepts stale.

\subsubsection{Record validation and revision}
\label{sec:knowledge-quality}

Deterministic checks detect malformed documents, unresolved citations, scope violations, and
invalid Science addresses. Changed or unavailable Science revisions and expired concepts produce
review diagnostics. These checks establish structural consistency and source identity, not whether
a cited paper supports a statement or whether its underlying finding is correct. Warnings may
remain in saved drafts; approval records permission to write, not certification of truth.

Scientific review requires examination of the underlying evidence. SwarmX retains source
references, inputs and outputs so that a reviewer can inspect an original passage or recompute
a result, as illustrated in Section~\ref{sec:examples}.

When an error is established, a curator can revise or deprecate the concept. Deprecation retains
its history and excludes it from default search; explicit inspection can still recover the failed
claim and its correction. Failed outcomes can thus remain useful negative experience without
remaining accepted guidance. Expiration is exposed as a stale flag rather than automatic removal.
Changes to revision-pinned prerequisites propagate stale flags through the concept graph.
Reassessing support, revising dependent claims and recomputing previously generated outputs
require explicit action.

% 中文：执行环境与安全边界
\subsection{Execution environment and safeguards}
\label{sec:safeguards}

% 中文：本地服务保有科研记录；模型执行和权限属于所选原生 Agent。
SwarmX services run on the user's machine and persist research records in workspace files, SQLite
Journals, content-addressed artifacts, and Markdown. LLM execution follows the selected native
Agent and its provider configuration. Python notebook and figure execution uses a configured
Docker image derived from the pinned Jupyter Data Science stack. The Host records the resolved
image, platform, Python and package versions. Each execution has no network, a read-only root
filesystem, dropped capabilities, bounded resources, and mounts limited to its workspace and
declared immutable inputs. If a plotting run fails, outputs from earlier runs are not registered
as its results.
The bundled Typst compiler
and explicit Git/DVC operations retain their host-process boundary; Zotero requires a configured
local service. Native agents execute under their own runtime permissions.

% 中文：宿主限制工作区与资源访问；原生运行时控制执行权限。
The Electron client uses context isolation and sandboxing. The Host enforces project scope,
session ownership and revision preconditions. Grants for Memory/Science access, runtime and model
selection, and delegation persist with conversations; delegated agents receive only the
intersection of the applicable grants. These controls govern Host APIs, while native filesystem
access and internal tools follow the selected runtime's permissions. Native approval requests
reach the connected user with their original options.

\section{Illustrative examples}
\label{sec:examples}

The current example connects native delegation, Docker computation, a registered figure,
a scoped claim and subsequent knowledge retrieval on the implementation in
Table~\ref{tab:code-metadata}. It reuses a six-row synthetic germination fixture: each group has
three replicates of 100 seeds, with control counts of 78, 80 and 79 and primed counts of 86, 88
and 87. These are demonstration values, not observations from a biological experiment.

\subsection{Analysis, verification and provenance}

A reproduction driver creates a fresh filesystem project, imports the CSV as an immutable
artifact and configures the bundled Docker environment. It supplies the lead Codex Agent with
the analysis code, dataset identity, tool-call specifications and the required workflow.
Automatic memory review is disabled and write approval is enabled for the run. Native permissions
retain the installed runtime configuration. The example evaluates a guided integration workflow.

The lead executes the supplied Pandas/Matplotlib analysis through the Science notebook tool.
It obtains means of 79\% and 87\%, a difference of eight percentage points, and registers the
figure with its code, input digest and execution environment. A separately delegated Codex
session recomputes the values from the same immutable input using Python's standard library
and checks its SHA-256 identity. Both computations run through the isolated Science runtime.
The separate computation checks the arithmetic and input identity in this fixture.

The lead records the descriptive claim and links its evidence to the input, generated figure
and notebooks. It then proposes a sourced Memory finding and exports the Science project as
RO-Crate. Figure~\ref{fig:desktop-record} shows the current browser client with the completed
analysis and registered figure. Figure~\ref{fig:desktop-provenance} shows the subsequent
retrieval beside the recorded computations.

\subsection{Test suite and integration checks}
\label{sec:tests}

On 7~September~2026, checks were run on macOS~26.6.2 arm64 using Node.js~26.7.0 and the
repository's pinned pnpm configuration. The full Vitest suite passed 345 tests with
seven conditional skips across 51 files. The six tests in the research-environment file also
passed with Docker enabled, including actual environment setup, versioned figure execution,
confinement and cancellation. Type checking, lint, documentation coverage, the complete
application build and the retained artifact verifier passed.

The automated suite covers recursive delegation and cancellation, persistent Host grants,
native failure propagation, journal ownership, memory revision and approval boundaries,
project isolation and the renderer interactions. The recorded example additionally exercises
authenticated Codex and the current browser client. These checks establish software behavior
and artifact integrity.

\section{Impact}
\label{sec:impact}

For agent-assisted projects, SwarmX provides continuity of research records. Science entities
and Memory concepts persist independently of a client session. In the example, a later session
retrieves the approved finding and its figure revision without rerunning the analysis. A reviewer
can follow that revision to the recorded input and computation. The same record and retrieval
mechanisms are available to an individual agent across sessions.

Project queries and revisioned locators connect conversations, computations, registered artifacts,
claims and later knowledge entries. Markdown, content-addressed files and RO-Crate also make the
record inspectable outside the client. This combination supports workflows in which one researcher
or agent produces an artifact and another checks its sources or reuses a documented finding.

The architecture also gives research-software developers narrow integration points. A disciplinary
tool can retain ownership of its simulator, database, or instrument while registering selected
inputs and outputs with Science. A conversation runtime connects through ACP without
reimplementing the scientific services. A collaborative workflow can use Swarm's recursive Agent
interface and explicit delegation. These interfaces are intended to let user interfaces, agent runtimes and domain tools evolve
independently while preserving links to research records. Reported use is currently limited to
the author-run example; third-party adoption and productivity have not been measured.

\subsection{Experience reuse and its evaluation}
\label{sec:reuse}

The software supports investigation of whether curated findings and procedures reduce repeated
searches or failed approaches in later tasks. Experience-memory methods provide precedents for
reuse~\cite{wang2023voyager,wang2024workflowmemory}; evaluating it in SwarmX requires checking
applicability to new inputs and accounting for retrieval, review and maintenance costs. Future
studies can compare curated memory with raw-history retrieval and no memory, and measure how
source and revision checks affect incorrect knowledge reuse under matched tools and budgets.

\subsection{Scope and limitations}
\label{sec:scope-limitations}

The pinned revision provides single-user operation, four upstream ACP integrations and external
ACP/A2A entry points. Controlled-peer tests do not establish authenticated deployment coverage
for every provider. Python execution requires Docker, literature search requires Zotero, and
versioned-data operations require Git/DVC; the Typst preview runtime is bundled. Signed desktop
installers, Windows deployment and import into named external provenance consumers are not
validated. An RO-Crate metadata export does not itself include every referenced data file.

Local exports require separate publication, licensing and archival arrangements for public reuse.
Native sessions follow their runtime's persistence contract, and Swarm membership is not durable.

The guided example uses fixed synthetic data to examine record and provenance behavior. It does
not establish autonomous discovery, multi-agent superiority, scientific error-detection rates,
generalization of saved experience or reduced inference cost. Background review and dependency
checks support curation, but the accuracy of extracted knowledge and correction of dependent
results require further evaluation on disciplinary workflows and independent users.

\section{Conclusions}
\label{sec:conclusions}

SwarmX connects native agent conversations, scientific computation, recursive delegation,
artifacts, manuscripts, and shared semantic memory through revisioned links.
The implementation provides append-only Science records, content-addressed artifacts, explicit
memory curation, and portable Markdown and RO-Crate outputs. It supports individual agents as well
as task-dependent multi-agent arrangements. Integration tests and the guided example demonstrate
the path from native execution to registered evidence, approved knowledge and subsequent retrieval,
providing an inspectable record across research sessions.
