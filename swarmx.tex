\begin{abstract}
Agent-assisted research fragments state across conversations, computations, artifacts, team actions,
and reusable knowledge. SwarmX is open-source orchestration software that connects these records while
preserving their authoritative owners. Runtime adapters retain native histories; Science manages
revisioned research entities and content-addressed artifacts; Swarm supports recursive delegation;
and shared semantic memory retains sourced knowledge under explicit revision and approval controls.
The software supports both individual agents and workflows that benefit from separate contexts and
review responsibilities. A guided synthetic-data workflow connects native delegation, separate
recomputation, an isolated plotting execution, a source-linked claim, approved memory and retrieval
in a later session. Current tests exercise the software's persistence and protocol boundaries.
SwarmX combines these services into an inspectable research record compatible with
retrieval-augmented generation. Its validation establishes software behavior and artifact integrity;
comparative multi-agent benefits, scientific error detection, and efficiency gains from accumulated
experience remain to be evaluated.
\end{abstract}

\section{Motivation and significance}
\label{sec:motivation}

LLM agents can search literature, run code, edit files, invoke instruments and services, delegate
work, and draft manuscripts. A single research result may consequently depend on a native
conversation history, several notebook or command executions, mutable workspace files, an
experiment record, review decisions, and knowledge carried into later sessions. These records have
different owners and lifecycles. A transcript records interaction but does not establish which
artifact version entered a claim; a file tree retains outputs but not the decision that admitted
them; and a workflow log does not by itself preserve the research question or later knowledge use.
The resulting fragmentation makes agent-assisted research difficult to inspect, resume, and
transfer.

These problems also occur with a single agent, which can use the same scientific records and
memory. Multi-agent execution is useful when a workflow has separable research branches, needs
distinct tool contexts, or assigns result production and review to different actors. Separate
contexts let an analyst examine data while a reviewer inspects original sources; explicit
delegation makes their responsibilities visible. This is a conditional design rationale, not a
claim that more agents are inherently more capable. A single agent can call tools concurrently
and check its own results, while a team adds communication and integration costs. Independent
review requires an additional evidence check, such as recomputation from the original input;
different role names alone do not establish independent errors. SwarmX supplies composition and
record ownership without prescribing how many agents a task should use.

The peer-reviewed AI Scientist automates computational
machine-learning research from ideation through manuscript review; Co-Scientist uses an
asynchronous multi-agent process to generate and refine biomedical hypotheses; and the Virtual Lab
combines an AI principal investigator and specialist agents with human feedback and wet-laboratory
validation~\cite{lu2026,gottweis2026,swanson2025}. ScienceAgentBench instead
evaluates 102 executable tasks drawn from 44 peer-reviewed papers and shows that current agents
solve only a minority, even when expert knowledge is supplied~\cite{chen2025b}.
SwarmX addresses the infrastructure below these research policies: durable ownership,
coordination, and linkage of the records produced by native agent runtimes and scientific tools.

Computational-provenance systems supply essential parts of this infrastructure. Whole Tale captures
reproducible environments, AiiDA manages computational workflows, noWorkflow captures Python
execution, and ProvBook enriches notebooks~\cite{brinckman2019,pizzi2016,pimentel2017,samuel2018}.
Workflow Run RO-Crate packages workflow executions, and PROV-AGENT represents agent interactions
~\cite{leo2024,souza2025a}. The FAIR principles and RO-Crate provide the exchange layer for
discoverable, reusable research objects~\cite{wilkinson2016,soiland-reyes2022}. SwarmX composes
these ideas around a cross-owner operational record rather than a new universal store.

Contemporary agent systems increasingly make claims and evidence first-class. ResearchLoop records
questions, evidence, claim ledgers, and closeouts in a repository-backed control plane; LEDGER
builds claim-to-evidence trace graphs over agent sessions; artifact-centered observability connects
scientific claims, artifacts, evaluations, and lineage; and PaperTrail presents claim-level
provenance for scholarly review~\cite{xia2026,kim2026,yin2026,martin-boyle2026}. Table~\ref{tab:related}
locates SwarmX within this landscape. Its software boundary combines service-owned research
records, recursive agent delegation, and explicitly curated shared memory.

SwarmX represents claims as first-class Science entities backed by the append-only Journal;
typed evidence relations connect a claim to a run, dataset or figure. Science exports this graph
as RO-Crate 1.3, providing an exchange point for external control planes and review interfaces.
Imports into ResearchLoop, PaperTrail, LEDGER or the Yin et al.\ observability profile have not
been tested. These systems address related tasks, and the export alone does not establish
interoperability with a particular consumer.

Retrieval-augmented generation (RAG) uses external knowledge to support generation
~\cite{lewis2020rag}, and Self-RAG combines retrieval with critique~\cite{asai2023selfrag}.
Experience reuse also has established precedents: Reflexion retains textual feedback, Voyager
accumulates executable skills, and Agent Workflow Memory extracts reusable procedures
~\cite{shinn2023reflexion,wang2023voyager,wang2024workflowmemory}. SwarmX's contribution is the
integration of source-linked scientific records with scoped, revision-controlled memory operations
across native agents. It does not introduce a new retrieval or experience-learning algorithm.
RAG can use this store as its knowledge source; retrieval and knowledge curation are complementary
functions. Other RAG systems can also provide provenance and lifecycle controls, so their presence
alone does not establish comparative superiority. The relevant evaluation is whether this
integration makes evidence easier to inspect and reduces incorrect or stale knowledge use.

Mokyr's useful-knowledge framework~\cite{mokyr2005} gives a broader rationale for joining
explanation and procedure. The framework distinguishes propositional knowledge about why a
technique works from prescriptive knowledge about how it is performed; it is one of the
influences drawn on in the scientific background for the 2025 Prize in Economic
Sciences~\cite{committee2025sustained}, where sustained progress is linked to lowering the
costs of finding, storing, transmitting, and verifying knowledge.
Applied to computational research, questions, hypotheses, claims, and evidence form the explanatory
record, while code, executions, configurations, workflows, and skills form the procedural record.
Their links allow a later researcher or agent to recover both the basis of a result and the process
that produced it.

We use these ideas with the FAIR principles as an institutional design lens for AI-assisted
science~\cite{mokyr2005,wilkinson2016}:
a durable knowledge substrate and commons boundary, interoperability infrastructure, epistemic
quality control, and governance and incentives. This four-layer organization is a synthesis used in
this article, not a taxonomy proposed by Mokyr. It separates the functions that software can supply
locally from the public archives, shared facilities, and incentive institutions on which cumulative
science also depends.

This article makes three contributions. First, it presents an architecture independent of a
particular client that connects native agent runtimes to append-only research records, content-addressed artifacts,
recursive delegation, sourced memory, and portable exports. Second, it specifies the boundary
between deterministic knowledge validation and scientific judgment, including explicit revision
and deprecation. Third, it provides executable artifact checks, current integration tests and a
recorded workflow linking native delegation, scientific artifacts and a subsequently retrieved finding.

\subsection{Software architecture}
\label{sec:architecture}

Figure~\ref{fig:architecture} presents two orthogonal views. The institutional-function view is a
directional constraint: L1 preserves explanatory and procedural knowledge; L2 connects scientific
resources; L3 makes results inspectable and contestable; and L4 governs authority and scarce
resources. The current release provides a local substrate, native integrations, deterministic
record checks, and explicit write approval. It does not itself constitute a public knowledge
commons or a funding, compute-allocation, credit, and reputation system; the dashed L4 boundary
marks this partial scope.

The operational-ownership view describes the implemented system: a client, native conversation
runtimes, SwarmX services, and user-controlled resources with portable outputs. The local Host
presents conversations and research objects to an Electron or browser client. It launches
unmodified upstream Codex ACP and Claude Agent ACP adapters, or the native Hermes and OpenClaw ACP
commands. Official ACP SDK connections carry session discovery, creation, reading, execution,
configuration and cancellation; recursive Swarms act as an ACP Agent upstream and ACP Client
downstream. Only the selected native integration loads. Native runtimes retain their histories,
agent loops, tools, authentication and permission semantics. The Host projects their reported
events into the client without taking ownership of native execution.

Each registered filesystem project owns its services, research records, execution journal,
settings and workspace memory. Product tools use Model Context Protocol (MCP); Codex, Claude and
Hermes receive the Host endpoint through their ACP session configuration, while OpenClaw retains
its gateway configuration. MCP carries tool calls, and ACP carries inter-Agent delegation.
External ACP and A2A entry points reach the same composition; the client uses AG-UI events.
Native histories and service-owned records remain authoritative. Renderer state and timing views
are transient projections.

\subsection{Software functionalities}
\label{sec:coordination}

% 中文：解释记录与过程记录通过版本、摘要与证据关系连接。
SwarmX operationalizes the useful-knowledge framework by linking rather than merging two families
of records. Questions, hypotheses, claims, and evidence form the explanatory chain; notebook cells,
experiment runs, artifact-generation records, code, and documented procedures form the procedural chain.
Revisioned locators, content digests, and explicit evidence relations connect the two across
services. This structure preserves both how a result was produced and why it entered the research
record.

% 中文：ScienceCore 为 Notebook、实验、图件、写作、科研记录、查询和导出提供紧凑工具接口，并可只读搜索本地 Zotero。只追加 SQLite Journal 记录科研实体及其关系，物化投影可由 Journal 确定性重建。工作区文件保持可变；文件注册为工件时经过类型核验、SHA-256 摘要和原子内容寻址发布。带 revision 的规范 sx 地址连接会话与这些对象，项目图可导出为 RO-Crate 1.3。图件还可以记录绘图代码摘要、脱敏运行环境和已核验输入来源。
ScienceCore provides a compact tool interface for notebooks, experiments, figures, writing,
research records, queries, and export, together with read-only search through the
\href{https://www.zotero.org/support/dev/web_api/v3/local_api}{Zotero local API}. An append-only
SQLite Journal records scientific entities and their relations, and materialized projections
rebuild deterministically from the Journal. Workspace files remain mutable; when a file is
registered as an artifact, it is type-checked, SHA-256-digested, and atomically published by
content address. Canonical, revisioned \texttt{sx:} addresses connect conversations to these
objects, and a project graph exports as RO-Crate 1.3. Figures can additionally record a
plotting-code digest, redacted execution environment, and verified input sources.

% 中文：当前 Swarm 是递归组合与显式委派；不提供旧原型的持久任务图与知识接纳状态机。
A Swarm exposes the same Agent interface as its lead, which may itself be another Swarm. The Host
provides explicit creation, status, session, message, and cancellation operations, with membership
held in memory. Delegation returns results while native agents retain their transcripts and
approval boundaries. The current implementation does not provide a durable research-task graph,
effect-recovery scheduler, enforced independent verdicts, or automatic knowledge admission.
Recorded parent--child execution links support inspection after a run; they are not a scheduler
that recovers unfinished scientific work. A delegated reviewer may recompute from the original
input, but separate role names alone do not establish independent errors.

\subsubsection{Knowledge curation and retrieval}
\label{sec:memory}

% 中文：Memory 通过显式整理积累知识；检索实现与知识治理相互独立。
SwarmX provides shared semantic memory implemented as owner-readable Open Knowledge Format
0.2 Markdown concepts. The store persists curated research knowledge across sessions and exposes
explicit search, read, create, update, deprecate, and lint operations through the Host's Memory
tool. Global and workspace scopes bound access; native agents retain ownership of conversation
histories and context management.

Memory records support source references, lifecycle metadata and SHA-256 revisions. Updates require
the previously read revision. The Host authorizes writes from a user-owned workspace setting;
per-write approval is optional and off by default. When enabled, writes become durable pending
proposals that only an authenticated browser action can approve or reject. A model-supplied
approval flag is rejected. Deterministic validation checks document structure, citations and
workspace-scoped Science references; it does not establish scientific truth.

Knowledge accumulates through explicit authoring and optional background review. A user or agent
records an outcome and its sources; review can propose notes or concepts from bounded conversation
and tool-event snapshots. Automatic review is enabled by default, after ten successful prompts
or ten tool calls in one turn, and can be disabled per workspace. The Host rejects observed review
tool calls and approvals and supplies no product-tool credential. Requested native restrictions
follow the unmodified upstream adapter; title suppression, ephemeral storage and complete internal
tool isolation are not cross-harness guarantees. Review candidates pass the same validation,
revision and configured write-approval checks. Updates preserve previous bytes and append to the
change log. Neither automatic extraction nor acceptance demonstrates generalizable learning,
and model weights are unchanged.

Search ranks textual matches in titles, tags, descriptions and bodies; a subsequent read returns
the concept and revision. Bounded user/workspace notes and a vault navigation index are frozen
when a session is initialized. Existing sessions retain that snapshot across restart; new
sessions see updated notes and index entries. Full concepts are retrieved on demand. Explicit,
revision-pinned prerequisite edges reject cycles and support ordered loading. Upstream changes
mark dependent concepts stale. These controls support retrieval-augmented workflows without
claiming a new retrieval algorithm or superiority to dense retrieval.

\subsubsection{Error detection and correction}
\label{sec:knowledge-quality}

Deterministic checks detect malformed documents, unresolved citations, scope violations, and
invalid Science addresses. Changed or unavailable Science revisions and expired concepts produce
review diagnostics. These checks establish structural consistency and source identity, not whether
a cited paper supports a statement or whether its underlying finding is correct. Warnings may
remain in saved drafts; approval records permission to write, not certification of truth.

Scientific review needs additional evidence. For literature-derived knowledge, the reviewer must
check the original passage, study conditions, corrections or retractions, and relevant conflicting
evidence; repeated citations to one source are not independent confirmation. For execution-derived
knowledge, successful process termination is insufficient: recomputation, expected-output tests,
unit checks, and examination of inferential scope can reveal silent errors. SwarmX records inputs,
outputs, and evidence links for such review, but supplies neither a general scientific-truth test
nor automatic surveillance of external literature. Agreement among agents does not replace these
checks.

When an error is established, a curator can revise or deprecate the concept. Deprecation retains
its history and excludes it from default search; explicit inspection can still recover the failed
claim and its correction. Failed outcomes can thus remain useful negative experience without
remaining accepted guidance. Expiration is exposed as a stale flag rather than automatic removal.
Changes to revision-pinned prerequisites propagate stale flags through the concept graph.
This is a dependency check, not a scientific re-evaluation: reassessing support, revising dependent
claims and recomputing previously generated outputs still require explicit action.

% 中文：执行环境与安全边界
\subsection{Execution environment and safeguards}
\label{sec:safeguards}

% 中文：本地服务保有科研记录；模型执行和权限属于所选原生 Agent。
SwarmX services run on the user's machine and persist research records in workspace files, SQLite
Journals, content-addressed artifacts, and Markdown. LLM execution follows the selected native
Agent and its provider configuration. Python notebook and figure execution uses a configured
Docker image derived from the pinned Jupyter Data Science stack. The Host records the resolved
image, platform, Python and package versions. Each execution has no network, a read-only root
filesystem, dropped capabilities, bounded resources, and mounts limited to its workspace and
declared immutable inputs. Missing setup fails explicitly without host-Python fallback. Failed
execution cannot register an old output as a newly successful figure. The bundled Typst compiler
and explicit Git/DVC operations retain their host-process boundary; Zotero requires a configured
local service. Native Agents are not claimed to share the research container's isolation.

% 中文：宿主限制工作区与资源访问；原生运行时控制执行权限。
The Electron renderer has no preload or Node integration, runs with context isolation and
sandboxing, and limits in-app navigation to the loopback origin. Browser permissions are denied
except for the configured same-origin clipboard-write operation. The Host and resource services
enforce project scope, canonical paths, session ownership and revision preconditions. Host grants
for Memory/Science reads and writes, harness/model admission and delegation intersect at each
delegation and persist with conversations. A native permission mode cannot widen those grants.
These checks govern Host APIs; native filesystem access and internal tools remain governed by the
selected runtime. They do not establish a cross-harness filesystem ceiling or an external-effect
recovery guarantee. Native approvals reach the connected user with their original options.

\section{Illustrative example and validation}
\label{sec:examples}

The current example connects native delegation, Docker computation, a registered figure,
a scoped claim and subsequent knowledge retrieval on the implementation in
Table~\ref{tab:code-metadata}. It reuses a six-row synthetic germination fixture: each group has
three replicates of 100 seeds, with control counts of 78, 80 and 79 and primed counts of 86, 88
and 87. These are demonstration values, not observations from a biological experiment.

\subsection{Analysis, verification and provenance}

A reproduction driver creates a fresh filesystem project, imports the CSV as an immutable
artifact and configures the bundled Docker environment. It supplies the lead Codex Agent with
the analysis code, dataset identity, exact tool argument shapes and the required workflow.
This is a guided integration example; it does not evaluate autonomous experimental design
or discovery of undocumented APIs. Automatic memory review is disabled and write approval is
enabled for the run. Native permissions retain the installed harness configuration; the driver
can answer only the enumerated SwarmX product-tool confirmation forms.

\section{Impact}
\label{sec:impact}

This article reports an author-run integration example, not a third-party adoption or
user-productivity study. The impact discussion therefore describes enabled research questions.

By making ownership, revision, and curation explicit, SwarmX enables research on how heterogeneous
agents preserve scientific rationale and reuse sourced outcomes without copying private native
transcripts. Persistent memory also benefits a single agent across sessions; its value is not
conditional on using a team.

Mokyr's framework~\cite{mokyr2005} maps onto the knowledge costs addressed by SwarmX. Project
queries and canonical locators support finding records; bounded reads and portable formats support
acquisition and transmission; revisions, content digests, and evidence relations support
verification. Researchers can therefore follow a result across a conversation, computation,
registered artifact, claim, manuscript, and later knowledge entry. Markdown, content-addressed
files, and RO-Crate keep the durable record inspectable outside the client.

The institutional stack makes the corresponding division of labor explicit. SwarmX contributes
local components at L1, concrete interfaces at L2, and inspectable evidence and diagnostics at L3;
native approvals and scoped curation provide a limited workflow form of L4. Public repositories and preservation
services must make the L1 substrate discoverable and accessible, facilities must supply authorized
compute or instrument endpoints at L2, scientific communities must perform independent criticism
and reproduction at L3, and funders and institutions must provide the allocation and reward
mechanisms at L4. Portable SwarmX records can inform those institutions but do not replace them.

The architecture also gives research-software developers narrow integration points. A disciplinary
tool can retain ownership of its simulator, database, or instrument while registering selected
inputs and outputs with Science. A conversation runtime connects through ACP without
reimplementing the scientific services. A collaborative workflow can use Swarm's recursive Agent
interface and explicit delegation. These separations allow user interfaces,
agent runtimes, and domain tools to evolve without migrating the research record into a single
application database.

For agent-assisted projects, the practical benefit is continuity of research records. Science
entities and Memory concepts persist independently of a client session, and a reviewer can inspect
the artifact and evidence revision behind a claim. Native sessions follow their runtime's
persistence contract; in-memory Swarm membership does not provide durable task recovery.

\subsection{Experience reuse and its evaluation}
\label{sec:reuse}

Correct, applicable experience could reduce repeated literature searches, avoid previously failed
approaches, and replace repeated code generation with an already checked procedure. These
mechanisms reduce the amount of work needed for a task rather than making each model inference
intrinsically faster. Reuse still requires checking applicability and evidence revisions; a result
computed for one input cannot be treated as the answer for a different input. Experience-memory
methods provide precedents for such gains~\cite{wang2023voyager,wang2024workflowmemory}, but their
results do not establish a benefit for SwarmX. Net savings must exceed the costs of extracting,
retrieving, checking, and maintaining the experience.

Three comparisons are needed to test these benefits. First, compare a single agent allowed to
self-check with a multi-agent workflow using the same models, tools, records, and total inference
budget; report result quality, latency, and total cost. Second, introduce known arithmetic,
citation-support, version, and applicability errors and measure missed errors, false rejections,
incorrect knowledge acceptance, and correction of dependent outputs. Third, evaluate a chronological
sequence of related new tasks using no memory, raw-history retrieval, and curated experience,
holding the retrieval mechanism constant where applicable. Include curation and review costs,
prevent future-task answer leakage, and report failures as well as successes. These are proposed
evaluations, not results of the current synthetic examples.

\subsection{Scope and limitations}
\label{sec:scope-limitations}

The pinned revision provides single-user operation, four upstream ACP integrations and external
ACP/A2A entry points. Controlled-peer tests do not establish authenticated deployment coverage
for every provider. Python execution requires Docker, literature search requires Zotero, and
versioned-data operations require Git/DVC; the Typst preview runtime is bundled. Signed desktop
installers, Windows deployment and import into named external provenance consumers are not
validated. An RO-Crate metadata export does not itself include every referenced data file.

The owner-held substrate is local and portable rather than a public scientific commons, and its
default export policy does not imply publication, open licensing, or archival preservation.
Likewise, provenance establishes lineage rather than scientific validity. Scoped access and
explicit approval do not provide institutional funding, compute allocation, credit, or reputation.
Claims about those outcomes require separate infrastructure and evaluation.

The examples use fixed synthetic data to isolate record and provenance behavior. They do not
establish multi-agent superiority, automatic scientific error removal, generalization of saved
experience, or reduced inference cost. Broader evaluation should examine disciplinary workflows,
independent users, and the comparisons in Section~\ref{sec:reuse}. Background review and dependency
staleness checks are implemented, but their availability does not establish accurate extraction,
scientific error detection or automatic correction of dependent results.

\section{Conclusions}
\label{sec:conclusions}

SwarmX connects native agent conversations, scientific computation, recursive delegation,
artifacts, manuscripts, and shared semantic memory through explicit ownership and revisioned links.
The implementation provides append-only Science records, content-addressed artifacts, explicit
memory curation, and portable Markdown and RO-Crate outputs. It supports individual agents as well
as task-dependent multi-agent arrangements, and its memory can serve retrieval-augmented workflows.
Current tests establish software boundaries, and the guided example links a current native
execution to registered evidence and later retrieval. Scientific correctness still requires evidence review, and stored outcomes
must not be equated with learned, generalizable experience. The next empirical question is whether
this combination reduces incorrect knowledge reuse and the total cost of subsequent research tasks.
